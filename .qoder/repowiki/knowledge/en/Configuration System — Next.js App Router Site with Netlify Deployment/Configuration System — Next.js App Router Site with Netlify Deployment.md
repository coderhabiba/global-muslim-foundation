## Overview

This repository is a static-leaning Next.js 16 site (App Router) plus an archived legacy static site. It has **no runtime configuration system** — no `.env` files, no `process.env` usage in application code, no feature-flag library, and no secrets manager. All "configuration" is compile-time / build-time, expressed as plain TypeScript config files consumed by tooling.

## Build & Runtime Configuration Files

| File | Purpose |
|---|---|
| `next.config.ts` | Next.js build/runtime config: enables `cacheComponents`, `partialPrefetching`, and defines permanent redirects from legacy `.html` URLs to clean App Router paths (`/about.html` → `/about`, etc.). Also redirects `/index.html` → `/`. |
| `netlify.toml` | Top-level deployment config for the Next.js site: `npm run build`, publish `.next`, uses `@netlify/plugin-nextjs`, sets security headers (`X-Frame-Options`, `X-Content-Type-Options`, `X-XSS-Protection`, `Referrer-Policy`, `Permissions-Policy`) on all routes, and long-lived immutable cache for `/*.svg`. |
| `legacy/netlify.toml` | Separate deployment config for the archived static site under `legacy/`: publishes root directory, mirrors the same security headers, caches `/assets/*` with `max-age=31536000, immutable`, and explicitly avoids a `/* -> /404.html` catch-all so Netlify's native pretty-URL resolution works. |
| `tailwind.config.ts` | Design-system configuration: defines the full color palette (primary `#0D7C66`, secondary `#855300`, gold accents, surface tokens), typography scale (`headline-xl` through `label-sm`), font families (`sans` → Plus Jakarta via CSS variable, `serif` → Playfair), and `darkMode: 'class'`. Content scanning is scoped to `./app/**/*.{ts,tsx}` and `./components/**/*.{ts,tsx}`. |
| `postcss.config.mjs` | PostCSS pipeline (autoprefixer). |
| `eslint.config.mjs` | ESLint v9 flat config using `eslint-config-next/core-web-vitals` and `eslint-config-next/typescript`; overrides default ignores. |
| `tsconfig.json` + `next-env.d.ts` | TypeScript compiler options; `next-env.d.ts` is auto-generated by Next.js. |
| `package.json` | Project metadata, scripts (`dev`, `build`, `start`, `lint`), and pinned dependencies (`next 16.4.5`, `react 19.3.0`, `tailwindcss ^3.4.19`). |

## Environment Variables

There are **zero** `.env*` files in the repository (confirmed by absence of any `process.env` or `NEXT_PUBLIC_` references in the codebase grep). The site does not load runtime configuration from the environment. Any external values (e.g., form endpoint URL in `app/api/forms/route.ts`) would need to be supplied at deploy time via Netlify's environment-variable UI — but none are currently referenced.

## Redirects as Configuration

The only application-level routing configuration lives in `next.config.ts` as a typed array of redirect objects:

```ts
const legacyPageRedirects = [
  'about',
  'appeals',
  'campaign-details',
  'impact',
  'volunteer',
  'zakat-calculator',
].map(page => ({
  source: `/${page}.html`,
  destination: `/${page}`,
  permanent: true,
}));
```

This centralizes the legacy-to-clean-URL mapping in one place rather than scattering it across pages or components.

## Security Headers Convention

Both `netlify.toml` and `legacy/netlify.toml` declare identical security headers (`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `X-XSS-Protection: 1; mode=block`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation()`). This is a deliberate convention carried over from the legacy static deployment into the new Next.js deployment.

## Conventions Observed

- Configuration is declarative TypeScript modules exported as defaults (`next.config.ts`, `tailwind.config.ts`, `postcss.config.mjs`, `eslint.config.mjs`).
- There is no runtime configuration loader, no config schema validation, no feature flags, and no secret management.
- Legacy URL compatibility is configured centrally in `next.config.ts` redirects rather than per-page.
- Netlify deployment settings live in two separate `netlify.toml` files — one for the active Next.js build and one for the archived legacy site — keeping the two deployments independent.
- Static assets served from `/public` get immutable caching via `Cache-Control: public, max-age=31536000, immutable` for SVGs in the main site and for `/assets/*` in the legacy site.
